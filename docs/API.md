# API Documentation

## Base URL
Local: http://localhost:4000
Production: https://yourdomain.com

## Response Format
Every endpoint returns the same structure:

Success:
{
  "success": true,
  "data": {},
  "message": "string"
}

Failure:
{
  "success": false,
  "data": null,
  "message": "string",
  "error": "error detail"
}

---

## Endpoints

### Health Check
Check if the API is running.

- Method: GET
- URL: /api/health
- Auth: None

Response:
{
  "success": true,
  "data": null,
  "message": "API is running"
}

---

### Submit Activity
Called when a user submits the activity form. Saves the submission and queues certificate generation.

- Method: POST
- URL: /api/submit
- Auth: None

Request Body:
{
  "name": "John Doe",
  "email": "john@example.com",
  "activityId": "web-dev-bootcamp-2024"
}

Validation Rules:
- name: required, string, min 2 characters, max 100 characters
- email: required, valid email format
- activityId: required, string, must exist in the activities list

Success Response (200):
{
  "success": true,
  "data": {
    "submissionId": "uuid-here",
    "message": "Your certificate will be emailed to john@example.com within 2 minutes"
  },
  "message": "Submission received"
}

Error Response - Validation Failed (400):
{
  "success": false,
  "data": null,
  "message": "Validation failed",
  "error": "email is required"
}

Error Response - Server Error (500):
{
  "success": false,
  "data": null,
  "message": "Something went wrong",
  "error": "Internal server error"
}

---

### Check Certificate Status
Check the status of a certificate generation job.

- Method: GET
- URL: /api/status/:submissionId
- Auth: None

URL Parameter:
- submissionId: the UUID returned from POST /api/submit

Success Response (200):
{
  "success": true,
  "data": {
    "submissionId": "uuid-here",
    "status": "completed",
    "generatedAt": "2024-01-01T10:00:00Z",
    "sentAt": "2024-01-01T10:00:30Z"
  },
  "message": "Certificate sent successfully"
}

Possible status values:
- pending    - Job is in the queue, not started yet
- processing - Certificate is being generated
- completed  - Certificate generated and email sent
- failed     - Something went wrong, check error field

---

## Error Codes
| Status Code | Meaning |
|---|---|
| 200 | Success |
| 400 | Bad request, validation failed |
| 404 | Resource not found |
| 500 | Internal server error |

## Notes for Developers
- All POST request bodies must be JSON
- Set Content-Type: application/json header on all requests
- submissionId is a UUID v4 generated by the backend
- Do not poll /api/status more than once every 5 seconds
